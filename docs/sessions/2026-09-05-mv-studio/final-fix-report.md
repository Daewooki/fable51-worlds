## C1 — command injection via the finalize prompt

**Was:** `spawn(BIN, quoteForShell(argv), { shell: true })` on `higgsfield.cmd`. cmd.exe
counts raw `"` to track quote state, so `\"` flipped it *off* and everything after `&` ran as
a separate command; `%VAR%` expanded inside the quoted argument. Neither is escapable from
outside a shell.

**Now:** there is no shell anywhere in the path.

- `resolveCli()` (`studio/server/finalize/seedance.mjs:32-56`) returns the absolute path of
  the **native** binary the npm package ships, or `null`. win32: `<npm root -g>/@higgsfield/
  cli/vendor/hf.exe`, with `%APPDATA%/npm/node_modules/...` as a fallback; the `npm root -g`
  probe is `spawnSync('npm', ['root','-g'], { shell: true })` with a fixed argv — no user
  input reaches it. Elsewhere: `<npm root -g>/@higgsfield/cli/vendor/hf`, `$npm_config_prefix/
  lib/node_modules/...`, then `which higgsfield`. Memoized per process.
- `detectCli()` (`:126-135`) and `runSeedance()` (`:169`) spawn that path with
  `shell: false` and the argv array verbatim. Unresolvable → `{ ok:false, reason:'higgsfield
  CLI not found (npm i -g @higgsfield/cli)' }` → manual mode, as before.
- `winCmdQuote` / `quoteForShell` deleted. The job card prints a POSIX single-quoted command
  line (`posixQuote`, `:79-82`) — copy/paste documentation, never executed.

**Folded-in minors:** `buildArgv` throws on a `job.mode` outside the four modes (`:60`);
`runSeedance` runs every `refs.*` filename through `path.basename()` (`:156-159`), so `../..`
cannot walk out of `projects/<id>/refs/`.

**Tests** (`studio/test/seedance.test.mjs`, 14 tests): `resolveCli()` returns a string ending
in `hf.exe` (win32-only, `it.skipIf`) — passes on this machine, resolving
`C:\Users\daewook\AppData\Roaming\npm\node_modules\@higgsfield\cli\vendor\hf.exe`; the four
existing `buildArgv` tests are unchanged and still pass; for the prompt
`x" & echo INJECTED %USERNAME%` the argv carries it as one element verbatim and the job card
contains the raw text (plus a POSIX-quoted command line); `posixQuote("it's")` round-trip;
unknown mode throws.

## I3 — unauthenticated server on every interface

- **Bind** (`studio/server/index.mjs:117-124`): `createServer()` is unchanged; the CLI entry
  listens on `process.env.STUDIO_BIND || '127.0.0.1'` and logs `(bound to <addr>)`.
- **Host allowlist** (`studio/server/ws.mjs:18-42`, applied at `index.mjs:56`): `localhost`,
  `127.0.0.1`, `::1`, `[::1]` and every LAN IPv4 from `os.networkInterfaces()`, any port;
  anything else → 403 `{ error: 'bad host' }`, checked before routing.
- **WS Origin** (`ws.mjs:57-68`): the upgrade is handled explicitly (`noServer: true` +
  `server.on('upgrade')`) so a non-allowlisted `Origin` **destroys the socket** before the
  WebSocket layer sees it. A missing `Origin` (native clients, tests) is allowed through and
  still needs the token for the phone room.
- **Phone token** (`ws.mjs:48`): `randomBytes(16).toString('hex')` once per process,
  `STUDIO_TOKEN` overrides. `GET /api/config` returns it as `phoneToken` (`index.mjs:96`); a
  `join` with `room:'phone'` and a wrong/absent `token` closes the socket with **4401**
  (`ws.mjs:73`); `director` joins need no token.
- **Clients:** `studio/app/src/phone.ts` puts `&token=` in the QR URL;
  `studio/app/phone/phone.ts` reads it from the query, sends it in `join`, and stops
  reconnecting on a 4401 (with a message telling the user to re-scan).

**Tests:** `test/api.test.mjs` — Host `evil.example` → 403 `bad host`; `localhost:<port>` and
`127.0.0.1:1` → 200; `/api/config` carries a token (raw `http.request`, since fetch will not
forge a Host). `test/ws.test.mjs` — relay still works with a valid token; phone join with no
token → 4401; with a wrong token → 4401; a tokenless socket relays nothing; Origin
`http://evil.example` → upgrade refused; localhost Origin → allowed.

## I6 — docs contradicted the code; no way to author a pose

`studio/app/src/main.ts:203-249` adds an **Unlock controls** toggle plus a `walk`/`orbit`
select under the viewport (`app/index.html`, `#viewport-controls`; styles in `style.css`).
Unlocking calls `bridge.call('setMode', { m })`; "Add key @ t" reads the live pose either way
(the `pos` handler reads `app.camera` directly). The toggle resets to locked whenever a shot
remounts the iframe. kyoto shows `n/a` (its adapter's `setMode()` is a documented no-op).

**One deliberate divergence from the ruling.** The ruling said "toggling off calls `setMode`
back to `'orbit'`". Reading `union-square-sf/src/main.ts:68-77`: `setMode('walk')` enables
`WalkControls` and disables `OrbitMode`; `setMode('orbit')` does the reverse (and reframes the
camera); `setMode('tour')` disables both **but starts the tour**, which moves the camera.
There is no mode string that re-locks. So re-locking passes an unknown-but-inert mode
(`'none'`): `walk.enabled = false`, `orbit.setEnabled(false)`, no tour, no reframe — exactly
the state `?studio=1` establishes at startup. Locking back to `'orbit'` would have left
OrbitMode enabled and fighting the scrubber, i.e. not locked at all.

Also documented (README, *Unlocking the camera*): unlocking hands over to the world's own
controller, which resumes from *its* last pose, so the view jumps once on unlock. That is the
world's behaviour, not something the Director can paper over without patching
`union-square-sf/` (out of bounds for this round).

README: the "flown by hand" paragraph is corrected in both places (walkthrough step 3 and the
Kyoto limitations list).

**One consequence worth calling out.** `launchWorld()` was sending only `qa=1`, so gating
kyoto's loop-park on `studio=1` would have broken the kyoto previz (its walker would re-seat
the camera every frame). `server/render/browser.mjs:11` now also sends `studio=1` — which is
what the world contract in `studio/README.md` has documented all along. For union-square-sf
this disables its own walk/orbit controllers during a render (previz's INSTALL already skips
them in `updatables` and drives the camera itself), and the StudioBridge it installs is inert
in a top-level page (`window.parent === window`). Verified by the full suite (both kyoto
integration tests, previz, export, browser) and by both e2e runs. Side effect: union-square's
1080p previz got ~25 % faster (0.65 → 0.48 s/frame).
