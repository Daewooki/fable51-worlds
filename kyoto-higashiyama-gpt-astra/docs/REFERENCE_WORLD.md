# Sakura Crossing: world-building implementation study

Inspected reference commit: `de01898e89c7f6ab3fad93fa802f0f5ac66fbd81` (cloned 2026-09-04). Source repository: https://github.com/Kenton-GMI/sakura-crossing . This is a study of the current code, whose scope has grown far beyond its original crossing; its spherical-planet machinery is deliberately inappropriate for a geographically grounded Kyoto corridor.

## Important corrections learned from the actual implementation

1. **Validate rendered ground, not a query against itself.** The repo documents a previous 75 mm terrain drop that made all bare-ground props float. It now uses a 15 mm clearance and compensates for interpolated grid chord error (`street.js:19–48`). Raycast geometry and compare against authoritative height samples.
2. **Avoid too-wide colliders.** A previous cherry collider closed a narrow footpath; the current collider is 1.15 times trunk radius, not 1.6 (`trees.js:158`). A route may look open and still be blocked.
3. **Maintain connected branch endpoints.** Trunk lean used to swap sine/cosine and detach the branch system. The corrected geometry computes the rotated actual trunk tip (`trees.js:45–68`).
4. **Draw calls can dominate.** The reference README reports approximately 1.74 million triangles and 19,000 meshes and explicitly records a draw-call bottleneck. Halving resolution did not fix it. Ordinary parked cars and repeated props should not each get outline shells; spatial batches should still frustum-cull. These are reference measurements, not Kyoto measurements.
5. **Global merging has a cost.** A world-spanning bounding volume cannot be culled. Kyoto's long route should merge per material within spatial cells, then instance repeated small objects within similar cells.
6. **Moving objects retain local pivots.** Although Kyoto will not use planet baking, any static merge must exclude noren/shutters/bells/cat rigs. Keep an outer placement group and an inner animation pivot.
7. **QA uses fixed camera capture.** `main.js:265` implements `window.__shot(name,W,H,opts)` and the Vite dev endpoint stores frames; preset positions are grounded from world height. Deterministic location, grade/ink toggles and direct image inspection are essential.

## Proposed Kyoto architecture contract

Build locally facing +Z, with a front plane at `d/2`; rotate once into world coordinates. Maintain coherent 4–8 m historic shop frontages, ground-floor headers around 2.5–2.8 m, upper rooms around 2.2–2.5 m, roof ridges parallel to street in typical hirairi machiya. Preserve recesses, wood lattice and low secondary street eaves. Create variants by tenancy, plaster/wood tones, lattice density and proportion rather than arbitrary whole-building styles. Final values and placement require real Kyoto references; these are modeling targets, not surveyed dimensions.
